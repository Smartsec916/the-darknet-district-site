## Existing integration to preserve or version

- `blackout-protocol/` is the GitHub Pages game at `/blackout-protocol/`. It has six HTML levels, a shared `engine.js`, menu, shop, completion and leaderboard pages. `games-list.html` links to that directory. The current game uses session storage for a run and browser-local scores for guests.
- `blackout-protocol/account.js` imports the existing `firebase-auth.js` and `district-identity.js`, supports guest play, handle-only Firebase accounts, email-link/Google upgrades, and calls `/api/blackout` with the signed-in user's ID token. It stores a server-issued ranked run ID in session storage. No second account system is needed.
- `blackout_api.py`, registered by `server.py`, verifies Firebase ID tokens with revocation checks, resolves the public handle, issues run IDs, checks ordered levels and score events, deduplicates submissions, and serves a global top 100 plus the signed-in player's best and exact rank. `BLACKOUT_ACCOUNTS_ENABLED=true` is required; the live Render value was not inspected. The six current score caps and event types are specific to the old game and must be replaced or versioned only after inspecting Tesana's scoring. Browser-submitted score evidence is bounded but not authoritative proof of play (see `blackout-protocol/FIREBASE-SETUP.md`).
- Existing `bp_profiles`/`bp_handles` hold account handles. `bp_stats`, `bp_leaderboard`, `bp_runs`, and `bp_submissions` hold old-game scoring. Keep accounts and handles; start a fresh, isolated Tesana leaderboard version rather than deleting or migrating old score records. The exact new validation and milestone event schema depend on the export.
- `static/blackout-protocol/` is a Render-served mirror: `server.py` serves its `index.html` at `/blackout-protocol/`. It is already **not identical** to the GitHub Pages copy: `account.js`, `index.html`, and `leaderboard.html` differ, with the static copy missing newer handle/email-link integration. The replacement needs an intentional build/copy process and tests for both hosts; do not blindly copy or drop the current account bridge. Direct refreshes and Vite asset URLs must resolve under `/blackout-protocol/`.
- Existing Firestore rule/index files are fragments for the old `bp_*` collections. Any new versioned collections need reviewed deny-browser rules and required indexes merged into the complete production configuration without replacing unrelated rules. No production database or rules were changed in this audit.
