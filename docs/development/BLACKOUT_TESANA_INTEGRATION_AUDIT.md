# Blackout Protocol — Tesana integration audit

Branch: `codex/blackout-tesana-integration`. Source is the owner's exact GitHub Release asset `blackout-tesana-import-2026/game-20261102-8d25f7e2-code.2.zip` (124 MiB; SHA-256 `fc021ef87001845f89f4e30112798048ad8f35a43be4d42e1d5fe2087833b2d6`). The ZIP passed `unzip -tq` and contains 12 sectors. The previous branch audit was written before this source became available; this document supersedes its source-pending checklist.

## Implemented on this branch

- `tools/blackout-tesana/` contains the exported TypeScript game, its 12 original level definitions, painted backgrounds, level-specific ads, Level 3 female NPC art, and a reproducible `build-and-sync.sh`. It excludes the 123 MiB `references/` archive, Tesana storefront metadata, and unused storefront art. Those are not loaded by the game. The script builds and copies the same output to GitHub Pages `blackout-protocol/` and Render `static/blackout-protocol/`. Existing old files and scores remain stored; the new `index.html` starts the Tesana game. It removes the Tesana play-SDK bootstrap, whose separate identity and cloud-scoring service conflicts with District accounts. No visible game watermark or mandatory attribution was found in the export. The supplied Tesana rights page could not be reached from this cloud network (HTTP proxy 403), so legal terms still need owner review.
- The game preserves its point values: coins 10, shards 50, relay sync 250, hacks 150, enemy values 100–400, bosses 5000, and the original completion time bonus. The bridge records these events without changing how points are earned. The main menu opens an Account / Top 100 panel. Guest play and local browser save remain available. The panel uses copies of the site's shared Firebase auth and District identity modules; signed-in runs use the server-verified Firebase UID and existing public handle. Auth changes invalidate the in-memory ranked run. Ranked runs start with a new game; a resumed local campaign is currently unranked.
- `blackout_api.py` adds `/api/blackout/v2/leaderboard`, `/v2/runs`, and `/v2/runs/<id>/level`. Version `tesana-2026-11-06` uses new `bp_tesana_*` collections; legacy `bp_*` scores are neither migrated nor deleted. The server verifies the Firebase token and handle, owns the player ID/run ID, checks ordered sector/time progression, recomputes score from bounded event counts, requires boss events in boss sectors, deduplicates submissions, and stores a best score and highest completed sector per player. The new leaderboard is publicly readable through the API and has a signed-in personal rank. A handle change updates both boards. The v2 service does not depend on the old six-sector feature flag; Firebase Admin credentials are still required.
- Accepted server event documents include stable game ID, version, level ID, and structured milestones (`level_completed`, `game_completed`, `personal_best`, `score_milestone`, `collectible_milestone`, `special_challenge_completed`) for a future site-wide achievement consumer. No badges or awards are created from browser claims. A Firestore deny-browser rules fragment for new collections is provided, but **production rules were not changed**.

## Verification and release boundary

- The exact unmodified export built with Vite and passed TypeScript. The integrated build also passes `npx tsc --noEmit` and `npm run build`.
- `python -m unittest discover -s blackout-protocol -p test_api.py`: **11 passed**. Tests include old API regressions, new score formula/limits, duplicate and cross-account rejection, all 12 sectors, fresh leaderboard isolation, and handle requirement.
- Headless Chromium loaded each of the 12 sectors locally with no page errors. The Pages and Render static copies returned 200 and displayed a mocked signed-in account/Top 100 on desktop and 390 px mobile with no failed asset responses. This is a render/smoke check, **not** a full playthrough or physical device test.
- This cloud network's proxy returns 403 for the live Render API and Tesana rights page. GitHub CLI's `GH_TOKEN` is invalid for GraphQL. Real Firebase sign-in, live Firestore rules/indexes, Render environment credentials, production score submission, and the production URL have **not** been independently verified. Do not treat mocked browser tests as proof of live account integration.
- Server validation constrains browser scores but cannot cryptographically prove gameplay from a client-side game. Stronger anti-cheat would require a trusted gameplay authority; no new paid service was introduced.

**Next release gate:** verify real Firebase sign-in and handle lookup, a v2 run/level submission, public Top 100, and the live Firestore rules against the deployed API environment. Recheck `origin/main` and Claude's branch before any merge. If those checks cannot be performed or fail, keep this branch off production. The owner authorized direct production deployment only after the required checks pass; no staging deployment is requested.
