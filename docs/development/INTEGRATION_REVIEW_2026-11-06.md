## Findings

- **Creator and wardrobe:** The first-run offer is tied to exiting pod 01, after the pod is available. The wardrobe is an interior interaction; confirm/cancel and existing-character paths are covered by the character tests. The server accepts catalog IDs only, requires a signed-in non-anonymous account with an existing character, and leaves the one-character record and campaign save alone. Hub and game appearance rules are byte-identical (`sync-hub-appearance.cjs --check`). The look remains browser-local while `VOID_APPEARANCE_ENABLED` is off. Outfits and shoes are whole-model presets, and Low uses the same 29k–40k triangle models as High. See `CHARACTER_CREATOR.md` for measured counts and the MPFB export list.
- **Hub and trading:** Production tokens are RS256-verified against Google's keys with project, issuer and time checks. The verified UID is used for the required test allow-list and deny-list; exact page origins, per-IP and total connection caps, room cap, message limits, bounds/speed checks, and one session per UID are in place. Appearance is validated again by the hub; a refresh requires another verified token for that same UID and is limited to one accepted change per two seconds. Only the District interior room is enabled. The deployed `server.cjs` calls `main()` without a ledger; production rejects `HUB_TRADING` and uses `DisabledLedger`. A ledger can be injected only by a direct caller passing the internal test-only `allowTestLedger` dependency, which the deployed entry point never does. Cosmetics are outside the trade catalog. Tests use signed local tokens, real loopback WebSockets, and a fake API, never live Firebase or Render. A refresh sent during a slow identity check is silently ignored; the new test pins this limitation. A later refresh can recover the latest saved look.
- **Deployment boundary:** `tools/district-hub/render.yaml` describes only the `district-hub` service under its own root directory, Free plan, Node 22, `npm ci --omit=dev`, `node server.cjs`, `/health`, and manual deploy. It cannot deploy GitHub Pages, the Flask API or Iris. `LIVE_HUB` is empty, so the published client cannot join a hub. The API appearance flag is off by default. Repository Firestore rule fragments deny browser access to `vr_players`, but the deployed complete ruleset, Auth authorized domains, App Check, billing plan, and current API Auto-Deploy branch remain unverified in their consoles.
- **Transition test:** A random street crowd imports many `crowd:*` skeleton nodes. The old total-node comparison mistook a larger later crowd for an environment leak. The test now compares non-crowd street nodes tightly while retaining mesh, texture, material, light, and interior cleanup checks. This changes only a browser test, not gameplay or graphics.
- **Stripe:** The previously reported webhook signature failure did not reproduce with Stripe 12.5.1, 13.0.0, or 14.4.2 (all allowed by `requirements-void-runner.txt`). The current full API suite passes. No production payment code or dependency range was changed without a reproducible cause.
