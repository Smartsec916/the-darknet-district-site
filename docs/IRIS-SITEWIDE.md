# Iris across the site

The Iris chat is on the homepage and on the other public pages: the arcade directory, About, the Sleeping Pod, the Resources hub and its nine resource pages, and the whole store (seven pages). It is never on a game, a game's interface, a standalone site, or the in-world Iris pages (`iris-*.html`).

## How it is built

- `iris-chat.js` is the chat itself: the API addresses, the window, the conversation, the phone layout. It used to be inside `script.js` and was moved out unchanged (apart from the saved conversation), so pages without it do not pick up `script.js`'s store and glitch effects. The homepage lists it in its HTML after `iris-identity.js`; nothing else about the homepage changed.
- `iris-widget.js` is the one line another page adds: `<script src="iris-widget.js" defer></script>` before `</body>`. It adds the same window and capsule button the homepage has, loads `iris-widget.css` first (so the button never shows up unstyled), then loads `iris-identity.js` and `iris-chat.js` once each. It does nothing if the page already has a chat button or has `<body data-iris-widget="off">`, so a page can never get two chats.
- `iris-widget.css` is generated by `node tools/build-iris-widget-css.cjs` from the homepage's own chat styles (the `<style>` block in `index.html` and the Iris rules in `accents.css`), re-scoped to `body.iris-widget-page`. A unit test rebuilds it and fails if it is out of date, so the two cannot drift. After changing the homepage chat styles, run the script.
- The backend, the request, the session handling, the rate limits and the logging are exactly the homepage's: the same `window.IRIS_API_BASE`, the same `/api/chat/message`, the same visitor id.

## Never

## The conversation follows the visitor

`iris-chat.js` keeps the session id, the message count and what has been said (the last 60 messages, 2000 characters each) in this tab's `sessionStorage`. The next page with the chat restores the same session (so Iris still has the thread on the server and a retry is still the same request), draws the earlier messages again, and does not repeat the welcome. It stays only in this tab, is cleared by "reset session", and is not used if storage is blocked (each page then starts a new conversation, as before). The window always starts closed, so it never covers a page the visitor has just opened. Transient notices ("waking up", "disrupted") are not carried on.

## Known limits

- A signed-in visitor chats on these pages as the same returning browser (the visitor id), not as their account: the sign-in button and its token live on the homepage only. Sign in on the homepage for the account.
- The `static/` mirror of the site is not changed.
