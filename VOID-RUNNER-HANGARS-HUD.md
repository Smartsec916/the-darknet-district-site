# VOID//RUNNER — transparent hangars and flight instruments

1. **Exit replacement.** Removed the old expanding rings, rectangles and exterior-station departure graphic. Four original rendered RGBA hangar interiors now surround the existing cockpit view. The doorway is an alpha cutout: the game's live sky and stars render behind it. The generated alpha is preserved, including antialiased edges (sampled aperture alpha 0–1 out of 255).
2. **Artwork.** Meridian has worn ivory alloy, curved ribs, amber windows and cyan beacons; Kepler has scratched freight decks, cargo stacks and yellow machinery; Rusthaven has rust, welded repairs and magenta lighting; Foundry has soot-dark heavy steel, cranes and orange work lights. See the asset table below.
3. **Placeholder status.** All four departure assets are implemented artwork, not geometric placeholders. No additional artwork is required for this update. These are 2D environments, not full 3D models. If an asset fails to download, departure continues over the live scene without substituting fake hangar geometry.
4. **Forward movement.** A cached 16×10 grid (320 triangles) maps the artwork around its optical center. Depth falls toward the image edges, so near floor, walls and ceiling expand faster than the distant exit. Camera advance follows squared departure progress, producing acceleration. The transparent opening grows until its frame passes beyond the viewport. Small triangle-clip overlaps prevent hairline seams. This is a perspective deformation, not uniform image enlargement.
5. **Duration.** Four simulation seconds, configured once in `VoidWarp.config.departureSeconds`. The aperture clears the view near the end. Existing pause and simulation timing are preserved.
6. **Normal flight.** `drawDeparture` returns before drawing unless the route phase is exactly `departure`. Tests assert zero hangar draws in alignment, warp, encounter and arrival. Cockpit and live scene remain; ordinary steering resumes through the existing route logic.
7. **HUD.** Thin Canvas heading tape, pitch ladder, full-circle bank reference with pointer, boresight, speed, thrust, pitch readout, missile count, conditional target range/closure and missile acquisition graphics. Existing hull/shield and route information remain with transparent panel backgrounds. Kestrel, Peregrine and Spectre use slightly different HUD colors with the same instrument layout. No new per-frame DOM elements or layout updates were added.
8. **Heading.** Normalize `flight.yaw × 180/π` into [0,360). N/E/S/W label the navigation reference axes, not a planetary magnetic field.
9. **Pitch.** `-flight.pitch × 180/π`. The engine's positive Y and pitch point down; negating them gives positive nose-up instrumentation.
10. **Bank.** `flight.roll × 180/π`; the pointer rotates with roll and the ladder counter-rotates. L/R and level are explicit. The reference scale handles inversion, verified at 180° in the math test. Existing controls still clamp roll to ±1.2 radians (about 69°), so normal play cannot reach inverted flight; controls were not changed.
11. **Ladder.** Marks every 10° use `tan((displayPitch − mark) × π/180) × min(width,height) × 0.45` for vertical offset, then rotate by negative roll about the boresight. Negative marks are dashed. The compact calibrated instrument is clipped to keep peripheral flight data clear.
12. **Tape.** Cached five-degree ticks and ten-degree labels scroll using the shortest wrapped heading difference. N correctly scrolls across the 359°/0° boundary; a fixed index shows current heading.
13. **Tracking.** The target box projects `missileLock.target` through the existing `flightPoint`, using the same camera basis as the enemy renderer. Existing off-screen hostile arrows remain. Range is the target's relative-position length. Closure is `(playerVelocity − targetVelocity) · unit(relativePosition)`, in simulation units per second; no invented real-world units or random telemetry.
14. **Missile integration.** `targeting.js` and `missiles.js` remain unchanged. The visual reads their target, progress and status. Open corner brackets become a complete compact LOCK box; the acquisition arc uses the actual configured lock radius and progress. There is no fallback selection of an unrelated enemy. Lock loss clears the target graphic on the next simulation/render frame, reacquisition starts fresh, and firing retains ownership, capacity, ammo and cooldown checks.
15. **Performance.** Static tick labels and mesh topology are cached. Hangar images load lazily at docking/launch, not as opening-screen prerequisites. A 1440×900 local Edge benchmark measured added HUD drawing submission at roughly 0.04–0.22 ms/frame and the departure mesh at approximately 2.0 ms/frame. These are CPU submission measurements, not guaranteed end-to-end FPS on every GPU. Normal flight incurs no hangar mesh drawing. Original startup check completed in 283 ms with an unrelated texture blocked.
16. **Verification.** 32 Node tests pass. Browser checks pass for transparent aperture compositing over a known colored background, all four station textures, all departure/normal-flight phase gates, moving targets, lock/loss/reacquisition/fire, simulation orientation and velocity, and real A/D/W/S/Q/R/Shift/X keyboard events. Existing combat, cockpit, overhaul, piloted-campaign, travel and startup regressions pass. Desktop and 390×844 captures were inspected. The local browser review also launched each station manually and inspected the distinct interiors; normal-flight disappearance and detailed control assertions are covered by automated browser checks. Network/account requests in the new regression are mocked offline; no real payments were made.
17. **Branch.** `codex/void-runner-hangars-flight-hud`.
18. **Commit.** The exact committed revision and integration base are recorded in the delivered `PACKAGE.txt` and final response. No push, deployment or main merge was performed.

## Reproduce

Serve the repository root on localhost port 5000. Run `node --test tests/*.test.cjs`, then the browser scripts with Playwright and installed Edge. `tests/hangar-hud-browser.cjs` writes screenshots and measured results when `VOID_SCREENSHOT_DIR` is set. `tests/travel-preview.html` is a localhost-only manual travel fixture with station launch buttons, automatic alignment and an encounter pause; it suppresses save writes. It is a QA fixture, not a replacement game flow.
